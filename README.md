# Clinic Desk

A clinic appointment management proof of concept built to the Sevida Labs Senior Full Stack Design Challenge. It uses React + TypeScript, NestJS, GraphQL, MongoDB, Kafka, and Docker Compose. See [architecture](docs/architecture.md), [database](docs/database-design.md), [events](docs/event-design.md), [security](docs/security.md), [deployment](docs/deployment.md), and [ADRs](docs/adr/).

## Run locally

Requirements: Docker Desktop with Compose.

```powershell
Copy-Item .env.development.example .env.development
# Replace the local passwords and JWT_SECRET with unique random values.
docker compose --env-file .env.development up --build
```

For one-click startup on Windows, double-click `scripts/start-dev.cmd`. On Unix, run `bash scripts/start-dev.sh`. These build and start the development stack in the background using `.env.development`. For other actions, use `.\scripts\app.ps1 -Mode development -Action down` in PowerShell or `bash scripts/app.sh development down`; supported actions are `up`, `down`, `logs`, and `ps`. Production is not a local Compose mode; select `production` in the GitHub Actions release workflow and deploy through Kubernetes. The app launchers reject production mode with that guidance.

Equivalent launchers are provided for Windows and Unix: `./scripts/app.ps1 -Mode development -Action up` in PowerShell, or `bash scripts/app.sh development up` in a Unix shell. Supported actions are `up`, `down`, `logs`, and `ps`; `up` builds and starts the stack in the background. Both launchers use `.env.development`. Production is not a local Compose mode; select `production` in the GitHub Actions release workflow and deploy through Kubernetes. The launchers reject production mode with that guidance.

The API loads `.env.development` when started directly with `NODE_ENV=development`; Compose receives the same profile through `--env-file`. MongoDB requires authentication: use `MONGO_APP_USERNAME` and `MONGO_APP_PASSWORD` for the app-scoped account, and `MONGO_ROOT_USERNAME` / `MONGO_ROOT_PASSWORD` only for administration. The Mongo port is bound to localhost. Open the UI at <http://localhost:5173> and GraphQL Playground at <http://localhost:3000/graphql>. Compose starts MongoDB as a single-node authenticated replica set, Kafka, and three fictional seeded doctors. Sign in using one of the development staff numbers configured in `STAFF_USERS`. With mock SMS delivery, the six-digit code is shown in the UI and API logs. The sample development accounts are `+15555550100` (admin) and `+15555550101` (receptionist); use international phone format.

Mock SMS does not accept arbitrary phone numbers: the number must be listed in the backend `STAFF_USERS` allowlist. To use other fake numbers for development, edit `STAFF_USERS` in `.env.development` as comma-separated `+<E.164 number>:<ROLE>` entries, for example `+15555550123:RECEPTIONIST,+15555550124:ADMIN`, then recreate the API with `docker compose --env-file .env.development up -d --force-recreate api`. The OTP is generated by the backend and displayed in the development UI; roles always come from this server-side list.

Production sign-in requires both the Twilio SMS code and a six-digit authenticator-app code. Generate a unique TOTP seed for each staff phone with `docker compose --env-file .env.development exec api node scripts/generate-totp-secret.js +15555550123`; add the printed key manually in the authenticator app as a time-based code with six digits and a 30-second period. Store the corresponding `+<E.164 number>:<BASE32_SECRET>` entries in the `TOTP_SECRETS` secret (comma-separated). Inject this secret through the production secret manager; do not put real seeds in examples, ConfigMaps, or source control. The development mock flow intentionally skips TOTP.

For backend development outside Docker, install Node.js 20+, run `npm install` in `backend` and `frontend`, start MongoDB/Kafka with `docker compose --env-file .env.development up mongo kafka zookeeper`, then run `npm run start:dev` in `backend` and `npm run dev` in `frontend`. The backend loads `.env.development` and builds a localhost Mongo URI from the app username and password unless `MONGODB_URI` is explicitly supplied.

## Release images

The backend uses `NODE_ENV=development` or `NODE_ENV=production` to select runtime configuration; production validates required Twilio, MongoDB, JWT, and TOTP settings and rejects mock OTP delivery. To build release images, run the GitHub Actions **Build and publish release images** workflow and select `development` or `production`. The choice sets the API image's default `NODE_ENV`, selects the matching GitHub Environment, and publishes API/frontend images tagged `<environment>-<commit-sha>` to Artifact Registry. Configure the required variables and Workload Identity Federation as described in [deployment](docs/deployment.md). Publishing images does not deploy them; runtime secrets and Kubernetes rollout remain deployment responsibilities.

## What is implemented

- Patient registration with required fields/email validation, generated IDs, name search, and pagination.
- Seeded doctor directory and appointment booking/list/cancellation.
- A single GraphQL schema with backend-enforced receptionist/admin authorization.
- 30-minute slot validation and MongoDB partial unique index for race-safe doctor/time booking.
- MongoDB transactionally persisted appointment and outbox event; Kafka publishing and notification consumer with event-id idempotency.
- Docker images for UI and API; local MongoDB replica set and Kafka via Compose; Kubernetes deployment examples.
- Initial unit tests for appointment time validation.

## Assumptions and known limits

- Clinic time zone defaults to Asia/Kolkata. Appointment starts are selected at 30-minute boundaries, stored in UTC, and displayed in the clinic zone.
- This is an administrative scheduling tool only; no diagnoses, prescriptions, medical history, insurance, or payment data is included. Use fictional data.
- Staff phone numbers and roles are configured server-side through `STAFF_USERS`. Production must set `OTP_DELIVERY=twilio`, provide Twilio credentials and `TOTP_SECRETS` through a secret manager, and replace the sample staff numbers with real authorized accounts. Production environment values are supplied to Kubernetes from ConfigMaps and Secrets; see `.env.production.example` for required variable names. Mongo connection URIs belong in Secret Manager, not ConfigMaps.
- The demo outbox publisher is intended for a single API replica. Use a lease/claim or dedicated worker before horizontal production scaling.
- KafkaJS consumer reconnection, a dead-letter queue, exponential retry policy, GraphQL query complexity limits, full appointment-list filtering, and access/audit telemetry require production hardening.
- GCP and Kubernetes design is documented and sample manifests are included; no cloud resources are deployed. Replace image names, configure GKE Secret Manager / Workload Identity, managed MongoDB, managed Kafka, HTTPS ingress, and observability.
